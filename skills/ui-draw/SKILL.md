# ui-draw：像人一样用画板，而不是调程序

你手上有一块**画板**（ui-draw MCP 工具）。它不是绘图 API：每次工具调用就是画板上的**一个手势**——选好笔的颜色粗细，落笔、拖动、抬笔。人和你看到的是同一块板：你在画，他在浏览器里实时看着；他也能直接上手画、框选写批注。

**核心纪律：绝不用"一次性生成整个界面"的思路调用工具。** 没有 render(json)，只有一笔一笔的画。

## 何时用

- 用户要新建一个界面/页面/组件 → 先画线框共创，定稿后再写代码
- 用户要改现有界面 → 先贴参考截图，在旁边画出改法，确认后动代码
- 用户只是问问题、不涉及界面 → 不用画板

## 重要：画板会自动保存，且按项目区分

每个项目一块画板，自动存到用户目录（`~/.ui-draw/projects/<项目名>/board.json`），地址形如 `http://127.0.0.1:4680/p/<项目名>/`。
所有 agent 共享同一个本地服务：**同一项目的多个会话画的是同一块板**，不同项目互不影响。
所以：新会话开局先 `inspect_board` 看一眼——如果已经有内容，那是上次的成果，**接着画**，不要重新支板。
`setup_board` 在画板非空时会被拒绝（防误清空）；确实要重来才传 `force: true`，或 `clear scope=board`。

## 完整流程（人类设计师的工作方式）

### 1. 支板开局（只在空画板时）
```
setup_board（选尺寸预设）
show_board（让人类看到画板）
```
新会话恢复了旧画板的话，跳过这步，直接 `show_board` 让他看。

**`show_board` 的打开方式**：默认（`opener=auto`）会把画板地址交给你，让你用**内置浏览器**（ZCode 桌面版的应用内浏览器）打开，人类边聊边看。
- 你的环境没有内置浏览器能力、或打开失败 → 立刻再调 `show_board` 传 `opener="system"`，改开系统默认浏览器
- 还失败 → 把地址直接给人类，请他手动打开
- 千万不要把地址晾着不管

### 2. 草稿层起稿（像用铅笔轻轻打稿）
- `layers switch 草稿`
- 细灰线：`width=1, color=#9ca3af`，直线用 dash
- 只画大关系：页面外框、分区线（导航/内容/侧栏）、主要组件的占位框
- **坐标全部吸附 20px 网格取整**（120、240、560……），对齐是线框图的生命

### 3. 退后看一眼
- `look_at_board`——像人退后一步眯眼看画面
- 自查：分区比例、留白、对齐。不对就 move_elements / 撤销重来

### 4. 线稿层正稿（像换针管笔描正稿）
- `layers switch 线稿`
- 容器/卡片/输入框/按钮 → `draw_rect`（按钮可带 fill 浅色底）
- 圆形头像/图标占位 → `draw_ellipse`
- 分割线 → `draw_line`；指向关系 → `draw_arrow`
- **所有文字一律 `write_text`**（标题 24-32px，正文/标签 14-16px，禁用徒手写文字）
- 一口气画完一个区域（比如先画完导航栏）→ `look_at_board` → 再画下一个区域

### 5. 请人类批注，然后等他说"改吧"
人类用「📝 批注」工具在画布上**框选区域 + 写一句说明**。批注不会打断你，也不用你轮询：
- 画完告诉他："你可以框选想改的地方写批注，写完在对话里说一声"
- 他说"改吧 / 我批注好了"之后，先读批注再动手：
  - `list_annotations` —— 待处理批注全文（按编号，含区域坐标）
  - `inspect_board` —— 清单顶部也会列出待处理批注
  - `look_at_board layer=批注` —— 直接看批注画在哪
- 想主动问他问题时，用 `add_annotation` 在具体区域圈出来提问（人类在浏览器里能看到编号和文字）
- 每处理完一条就 `resolve_annotation`（按编号或 id），别攒着

### 6. 修改迭代
- 挪位置 `move_elements`（dx/dy 吸附 20 的倍数）
- 删错件 `delete_elements`（id 从 inspect_board 拿）
- 整步反悔 `undo_redo`
- 改现有 UI 的场景：先 `layers add 参考` + `paste_reference` 贴现状截图，在旁边画改法

### 7. 定稿交接
```
finalize_design → design/ 目录生成设计包
```
批注不进 design.png/design.svg（那只是反馈），但会记进 DESIGN.md 的「过程批注」。
然后**先读 design/DESIGN.md 和 design.png**，再开始写 UI 代码。实施中拿不准细节就回去看设计包。

## 禁忌

- ❌ 用 draw_stroke 手写文字、画矩形轮廓（有专门工具，徒手只画不规则曲线）
- ❌ 画 30 笔不看一眼（人类每画完一块都会端详）
- ❌ 跳过草稿直接正稿（小改动除外）
- ❌ 定稿后不读 DESIGN.md 就开写
- ❌ 人类正在批注时连续大改（等他画完）
- ❌ 新会话看到已恢复的画板就 setup_board 重来
