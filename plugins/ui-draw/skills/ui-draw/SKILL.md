# ui-draw：绘制完整界面

用 ui-draw MCP 画板逐区域绘制中高保真静态界面，交付完整页面、适用的主要状态与简短交互说明。绘图工具是逐笔手势，页面内容和视觉决策由你完成。用户可观看和批注；默认自主画完并自查。任务还包括 UI 代码时，先展示设计并等待用户确认，确认后才实施。用户已有确认或更具体的指令时依照用户要求。

## 1. 明确范围与尺寸

- 查阅用户需求、现有页面和设计规范。改造现有界面时，取得可用的现状截图作为参考；不把未确认的业务行为当成事实。
- 列出页面用途、主要区域、真实或合理示例文案、操作、适用的主要状态及其触发条件、视觉参考和必要假设。无需为每页机械套用所有状态：如登录页可能需要默认、校验失败、提交中；列表页可能需要有数据、空数据和加载失败。缺少关键事实且无法自行查明时再询问用户。
- 区分**目标浏览器视口**与**完整页面画布**。优先使用用户指定尺寸，再参考项目既有页面和截图；能可靠取得目标产品浏览器内容区域时使用实际尺寸，否则按 1440×900 视口规划并在交付时说明。画板所在侧栏的宽度不代表目标产品视口。
- 长页面固定目标视口宽度，按完整内容预估画布高度并留余量；视口高度用于判断首屏。图元应处于画布内，画到边界外不会自动扩板，默认导出可能裁切。当前支持宽 200–4096px、高 200–16384px、面积不超过 33554432 像素。画布不够高时用 `resize_board height=<目标高度>` 无损扩展（可撤销，保留原宽）；不能缩小。超出限制时说明能力缺口，临时分段须明确标记，不能当成完整单画布交付。

## 2. 准备画布

- 先 `list_boards`；第一次调用时传 `project_dir=当前项目的绝对目录`，确保插件市场安装的 MCP 进程落在用户项目而非插件目录。若不知道路径，先从 agent 的工作区信息或命令行取得，不要猜测。后续工具可省略此参数；直接 `setup_board` 或 `inspect_board` 作为第一次调用时也可传 `project_dir`。有画布时再用 `inspect_board` 等工具按本次任务识别目标，无画布时直接新建。仅在确认继续既有页面和状态时 `switch_board` 接续。最近使用的画布不一定属于当前任务，不清空或覆盖已有成果。
- 默认每个页面状态一块画布，标题如「登录页 - 默认」「登录页 - 校验失败」。新状态使用 `setup_board` 并同时传完整 `width`、`height`，通常设置 `grid=false`；同名时先辨别是否继续或取不冲突的标题。用户要求状态总览时，额外绘制总览，不替代各状态。
- `show_board` 让用户查看画布：取得地址后确认是否已打开；若工具只返回地址，则优先用当前环境可用的应用内浏览器打开，不可用时用 `opener="system"`，仍失败则交付地址。需要参考截图时先 `layers add 参考`，再 `layers switch 参考`、`paste_reference`，完成后切回草稿或正式图层；参考图不是最终页面。

## 3. 逐区域绘制完整页面

- 用 `layers switch 草稿` 切到草稿层，以简单轮廓验证页面分区、首屏和长页面结构；小范围改动可直接在已有设计上调整。使用 `look_at_board` 检查整体布局。
- 用 `layers switch 线稿` 切到正式图层，再确定背景、颜色、字号层级、间距、圆角和组件样式。绘制完整导航、内容、示例数据、表单、按钮和辅助文案；避免将大面积占位框作为最终交付。实际缺少的素材可标注占位并说明。
- 用 `draw_rect`、`draw_ellipse`、`draw_line` 等绘制组件，用 `write_text` 写文字；图像可用 `paste_reference`。按区域绘制和查看，用合适的间距对齐，不强制所有坐标为 20px 的倍数。
- 先完成默认状态，再绘制适用的其他状态，保持页面公共布局、文案和样式一致，只改变该状态需要变化的内容。状态是静态设计，不声称已实现交互。

## 4. 批注与修改

- 在关键区域用 `add_annotation` 做少量说明，解释触发条件或画面无法直接表达的行为；正式批注不是在批注层用 `write_text` 写普通文字。批注会保存在画布数据和过程记录中，但默认不进入最终 PNG/SVG。
- 用户希望共创或要求先评审时，在约定节点等待；用户说已批注后用 `list_annotations`、`inspect_board` 或 `look_at_board` 读取，再逐条修改、复查并 `resolve_annotation` 已处理的反馈。用户正在批注时等待其完成。说明性批注可能也是 open 状态，按作者和内容与用户反馈区分；不把说明性批注冒充已解决的用户反馈。
- 使用 `move_elements`、`delete_elements`、`undo_redo` 修改；移动或删除前先核对图元 ID。用户未要求清空时保留既有画布。

## 5. 自查、导出与交付

对每个状态先用 `look_at_board` 检查整页和必要的局部：主要内容和操作齐全，文字可读且不重叠、截断或越界；组件样式、对齐和间距一致；长页面及状态差异完整。处理问题后复查。隐藏草稿和不属于最终页面的参考层，确认未处理的用户反馈状态。

逐画布用 `finalize_design` 导出设计包，先检查导出目录是否已存在或与其他标题归一化后的路径冲突；必要时显式指定不冲突的 `dir`，避免覆盖已有成果。实际查看每张导出的 `design.png`，并核对 `design.svg`；大型画布的 PNG 倍率会自动降低，以工具返回的实际倍率为准，必要时通过区域截图看细节；现有 PNG 和 SVG 的跨图层顺序可能不同。注意隐藏层的文字和颜色仍可能出现在自动生成的 `DESIGN.md` 清单中，检查后说明。若输出裁切、缺内容或格式不一致，修复后重新检查，无法修复时说明限制。

在设计交付目录另写一份页面交互说明：记录目标视口及依据、各状态与触发条件、主要操作及状态关系、假设、未覆盖内容和工具限制。在聊天中列出画布或设计包位置及说明。用户只要求设计时到此交付；还要求代码时，展示设计并等待用户确认，确认后读取对应 `DESIGN.md`、`design.png` 和交互说明再实施。
